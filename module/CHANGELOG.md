# 更新日志

## v1.7.11（2026-11-06）
- **新增「撤销模块全部改动」**（WebUI「工具」）：把本模块禁用过的所有应用和组件恢复成出厂状态，清空拦截清单（原清单先备份），还原 CPU 上限。不删数据、不用重启。账号登录异常、桌面卡片不显示时使用。
- **新增「保持 USB 调试 / 无线调试」**（WebUI「工具」，默认关闭）：关闭开发者模式后，模块自动把 USB 调试打开回来；无线调试在连着 Wi-Fi 时自动打开（Android 11 以上才有）。临时 root 重启后，要等重新获取 root、模块启动后才生效。
- **新增「导出诊断报告」**（WebUI「工具」）：遇到问题时一键生成报告到「下载」目录，点「在文件管理中打开」，长按报告选「发送」用 QQ、微信发给作者；也可以「复制报告」直接粘贴进聊天框，或去 Gitee 反馈。只读，不含账号、手机号、IMEI、应用列表。
- **修复取消勾选后不生效**：WebUI 里取消勾选的项现在一定会发出启用命令，不再依赖状态检测（部分机型上组件状态读不准，会出现「取消了但仍被禁用」）。
- **默认不再拦截「桌面卡片云配置」**（com.oplus.pantanal.ums）：拦截它会导致桌面/主题的组件卡片、流体云不显示。已经被禁用的，用「撤销模块全部改动」或在 WebUI 里取消勾选后点「应用」即可恢复。
- **兼容老内核的高通机型**：限频节点在 /sys/module/msm_performance 下的机型（如 4.14 内核）也能识别。没有备份时的「出厂值」兜底，非 Ace 2 Pro 机型改用本机每核硬件上限，不再套用 Ace 2 Pro 的档位。
- **联发科/天玑机型不再空转**：没有高通 msm_performance 节点时，温控性能显示「本机不支持」，守护不启动、不改 CPU 频率；安装时会提示。
- **新增「游戏记录」**：自动记录每局游戏的平均/最低/最高帧率与 1% Low、大核/中核/GPU 频率、机身最高温度、满频时间占比、掉电。
  游戏在前台才算（切后台超过 30 秒或退出即结束一局），保留最近 50 局；清空前会另存，可恢复。
  帧率以「对局段」（游戏切到最高刷新率的那段，如 90/120Hz）为主显示，大厅 60Hz、加载/结算等静止画面不计入。
  - **卡顿统计**：对局里低于刷新率 90% 的秒数、占比和最长连续卡顿。
  - **曲线**：点「曲线」查看整局帧率与机身温度的变化（每 10 秒一个点）。
- **游戏切到后台自动收回满频**：「仅游戏」模式以前只看游戏进程在不在，王者退到后台进程常驻，桌面上也一直满频。
  现在只在游戏处于前台时满频，切出去 15 秒后收回（回微信、拉通知栏这种短暂切出不会来回切换）。
- **每个游戏单独设温度阈值**：在「游戏记录」里点「温度阈值」，没设的游戏跟随全局阈值。
- **修复「关闭并还原」约 2 分钟后又自动满频**：关闭现在会保存为关闭状态，看护循环和重启都不会再自动打开。
- **温度滞回生效**：超过阈值收回后，要降到「阈值 − 3°C」以下才重新解锁，不再在阈值附近反复切换。
- **出厂上限备份更可靠**：不会把空值或已解锁的值当作备份，避免以后还原失败。
- **卸载不再写死 Ace 2 Pro 的档位**：优先还原本机备份的原值，其他机型卸载更安全。
- 守护更省电：温区号缓存、游戏检测一次扫描、「指定应用」模式不再每 5 秒跑 dumpsys。
- WebUI：开启失败会如实提示错误；关闭后「开启」按钮可直接点。
- **修复新装机型上所有守护都不启动**：安装包里脚本没有执行权限（644）时，开机自检会全部跳过，
  温控解除和游戏记录都不生效（日志里只有「看护循环已启动」，没有后面两条）。安装脚本现在会显式设权限。
- **修复新机型温度保护失效**：没有 `skin-msm-therm` 温区的机型（天玑、骁龙 8 Elite 等）以前读不到温度，
  或退到一个不随负载变化的外壳温区上（实测满频时外壳仅 37~40°C，甚至三个 shell_* 同值不动），等于没有保护。
  现在按「机身表面 → CPU 结温 → 外壳」自动换温区；用 CPU 结温时阈值自动切到单独的高温档。
  **WebUI 里现在有两个阈值滑杆**：「机身/外壳」55°C 与「CPU 结温」80°C，各管一档，只按当前温区那档生效。
- **每个游戏的温度阈值改为「相对全局」**：以前存绝对值，在 CPU 结温机型上会变成荒谬的数字。现在存差值，换机型仍然合理；旧的绝对值配置自动兼容。
- **游戏记录支持天玑 GPU**：以前只读高通的 kgsl 节点，天玑上 GPU 一栏永远是空的。现在自动识别 GED 与 gpufreq 节点。
- **诊断报告大扩充**：新增天玑专项探测（fpsgo / gbe / mtk_core_ctl / fbt_cpu / thermal_message / GED / dvfsrc）、
  高通新平台（lmh 频率限制、walt）、cpuset 与 uclamp 现场、全部温区（并标出模块会选哪个）、
  冷却设备状态、频率是否被钉住（连续采样）、ColorOS 温控档位表与老化属性、
  组件拦截失败的真实原因、守护起不来时的 SELinux 拒绝与权限排查。
- **诊断报告新增「限频链路取证」**：临时开内核 trace（约 10 秒，读完立即关闭并还原缓冲），
  用 `power/cpu_frequency_limits`（内核通用事件，带调用者）回答「到底是谁在给 CPU 设上限」，
  用 `schedwalt/update_cpu_capacity` 的 `thermal_cap` 与 `arch_capacity` 判断「是不是温控干的」
  （两者相等即证明与温度无关）。OPLUS 机型另有 OMRG 状态机事件。输出会聚合成统计，报告不会因此变大。
- **修复「实际被压却显示已满频」**（重要）：以前只按解锁节点判断，节点是解锁值就报「已满频」；
  但节点解开不等于频率真的上去了 —— 实测有机器节点已是解锁值、实际频率仍被压在 19%。
  现在改为比较每个核心组的实际上限与硬件上限，并**采样取最小值**
  （别的链路在毫秒级来回翻转，单次读数有约十分之一概率误报「没被压」）。
  状态改为「已满频 / 已解除但被别的链路压着 / 待命」三种，并列出被压到百分之多少。
- **诊断报告文件名带机型**：形如 `ColorOS温控与云控-诊断-PJA110-20261106-1530.txt`，
  一次收多台机器的报告时便于分辨。
- **修复诊断报告里「组件在不在包里」恒为「不存在」**：改用整包 dump 做匹配
  （`dumpsys package <包>/<组件>` 这种写法 AOSP 不支持，只会返回找不到包）。
- **修复「仅游戏」模式的文案自相矛盾**：以前只要本层没解锁且频率低于硬件上限就报
  「待命（本层未解除），且实际频率被压」—— 但「仅游戏」模式没开游戏时，节点本来就被还原成出厂值，
  这是设计如此。用户一打开 WebUI（游戏必然不在前台）就看到这句，以为模块坏了。
  现在只在本应满频时才报「被压」，否则照常显示「待命 · 游戏在前台时满频」。
- **更新日志支持折叠**：每个版本默认限高约 210px，超出部分显示「▼ 展开全部」，
  点开后变「▲ 收起」。以前最新一版几十条会把面板撑得很长，想翻旧版本要滑很久。
- **修复豆包/豆包输入法被误判为游戏**：游戏名单不再读 `uxicons/game_app.png`（非游戏也有这个图标），只用游戏空间的启动记录。
- 守护单次检查从约 0.8 秒降到约 0.1 秒（去掉大量外部命令调用）。
- 修复内存面板「停止」按包名前缀误判；云控快照回滚改用当前目录的归属与 SELinux 上下文。
